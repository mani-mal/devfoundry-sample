Title: Add migration runner and migration history checksums

Prerequisites:
Accepted remote commit 46825d3 on main (T002: opsledger/core/db.py with
connect(path) returning a sqlite3.Connection with foreign_keys=ON,
journal_mode=WAL, synchronous=NORMAL, row_factory=sqlite3.Row,
isolation_level=None, and transaction(conn) as a context manager that
BEGINs IMMEDIATE, commits on clean exit, rolls back on exception, and
raises ConflictError on nested use; opsledger/core/errors.py with
ApplicationError/ValidationError/NotFoundError/PermissionDeniedError/
ConflictError; tests/unit/test_db.py has 13 passing tests; bash check.sh
exits 0 with 45 Python + 2 JS tests).

Goal:
Make schema changes reproducible and tamper-evident. This task does not
add business tables, HTTP routes, authentication, or business modules.

Current contracts:
- opsledger/core/db.py: connect(path), transaction(conn) as above.
- opsledger/core/errors.py: ConflictError (code "conflict"),
  ValidationError (code "validation"), ApplicationError(message, *,
  code=None, fields=None) with to_payload().
- No opsledger/core/migrations.py exists yet. No opsledger/migrations/
  directory exists yet. No schema_migrations table exists yet.

Required behavior:
1. Add opsledger/core/migrations.py with a runner:
   migrate(conn, directory) that:
   a. Creates the schema_migrations table if absent: id INTEGER PRIMARY
      KEY, migration_id TEXT NOT NULL UNIQUE, checksum TEXT NOT NULL,
      applied_at TEXT NOT NULL (RFC3339 UTC with Z, second precision).
   b. Lists *.sql files in directory, sorts them by their numeric prefix
      (NNN_name.sql); a file without a numeric prefix raises
      ValidationError (stable code "validation").
   c. For each not-yet-applied migration, runs its statements inside one
      transaction(conn) block, then records (migration_id, checksum,
      applied_at) in the same transaction. migration_id is the filename
      without the .sql suffix. checksum is the sha256 hex digest of the
      exact file bytes.
   d. Skips already-applied migrations whose recorded checksum matches
      the file's current checksum (a no-op second run).
   e. Refuses an already-applied migration whose file content changed:
      raises ConflictError (stable code "conflict") naming the
      migration_id, before running anything. Nothing is applied when any
      checksum mismatch exists (check all first, then apply).
   f. Missing gaps are allowed: applied 001 with missing 002 in the
      directory is not an error; 002 applies when it reappears.
2. Add opsledger/migrations/0001_initial.sql creating one table:
   schema_notes (id INTEGER PRIMARY KEY, note TEXT NOT NULL). This is a
   runner fixture, not a business table.
3. Add tests under tests/unit/test_migrations.py covering: empty
   directory migrates nothing and creates schema_migrations; 0001
   applies and records checksum + RFC3339 Z applied_at; second run is a
   no-op (row count unchanged); editing an applied file raises
   ConflictError on the next run and applies nothing; a file without a
   numeric prefix raises ValidationError; a statement failure inside a
   migration rolls back both the statements and the history row.
4. Update docs/architecture.md with the actual public interface of
   opsledger/core/migrations.py and the migration conventions (numbered
   files, checksums, append-only rule).

Acceptance:
- bash check.sh exits 0.
- python3 -m unittest tests.unit.test_migrations -v exits 0.
- A fresh database migrates 0001; running migrate again changes nothing.
- Editing the applied 0001 file makes the next migrate raise
  ConflictError without applying anything.

Allowed paths: opsledger/core/, opsledger/migrations/,
tests/unit/test_migrations.py, docs/architecture.md. Preserve all
bootstrap behavior and the T001/T002 modules unchanged.

Constraints:

- No new external packages, network access, credentials, or generated
  data.
- No deletion, skipping, or weakening of accepted assertions.
- Standard-library sqlite3 and hashlib only; parameterized SQL;
