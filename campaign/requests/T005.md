Title: Add HTTP router and JSON error envelope

Prerequisites:
Accepted remote commit a7e4712 on main (T001: opsledger/core/errors.py
with ApplicationError(message, *, code=None, fields=None), to_payload(),
and ValidationError/NotFoundError/PermissionDeniedError/ConflictError
subclasses with stable default codes validation_error/not_found/
permission_denied/conflict; opsledger/core/clock.py; opsledger/core/db.py
from T002; tests/unit/test_core_errors.py, test_clock.py, test_db.py;
bash check.sh exits 0 with 45 Python + 2 JS tests).

Goal:
Create the HTTP foundation later handlers build on. This task adds only
routing, the JSON error envelope, and bounded input handling. It does
not add authentication, business tables, business services, or
persistence behavior beyond reading the request body.

Current contracts:
- opsledger/core/errors.py: ApplicationError with .code, .fields,
  to_payload() -> {"code": ..., "message": ...}; subclasses
  ValidationError (validation_error), NotFoundError (not_found),
  PermissionDeniedError (permission_denied), ConflictError (conflict).
- No opsledger/http/ package exists yet. No HTTP server code exists yet.

Required behavior:
1. Add opsledger/http/ package with a small adapter around
   BaseHTTPRequestHandler/ThreadingHTTPServer:
   a. Router: exact-path matching for explicit routes; a route handler
      receives the request and returns (status, body dict). Unknown
      path returns 404; a known path with a disallowed method returns
      405 with an Allow header.
   b. JSON error envelope: every error response is
      {"error": {"code": "<stable code>", "message": "<public
      message>", "request_id": "<opaque id>"}}. ApplicationError
      subclasses map to their .code; unexpected exceptions map to
      code "internal_error", HTTP 500, message "internal server
      error" (no traceback, no exception text in the response).
   c. Bounded input: request bodies over a configured limit (default
      1 MiB) return 413 with code "body_too_large"; malformed JSON on
      JSON routes returns 400 with code "malformed_json"; a non-JSON
      content type on JSON routes returns 415 with code
      "unsupported_media_type".
   d. Loopback by default: the server binds 127.0.0.1 unless
      explicitly given another host.
2. Add one example route GET /api/v1/healthz returning
   (200, {"status": "ok"}) so the router is exercisable end to end.
   This is a router fixture, not the T006 readiness handler.
3. Add tests under tests/unit/test_http.py using the handler classes
   directly against a local ephemeral-bound server (127.0.0.1, port 0)
   covering: unknown route -> 404 envelope; disallowed method -> 405
   envelope with Allow; malformed JSON -> 400 envelope; oversized body
   -> 413 envelope; wrong content type -> 415 envelope; a raised
   ValidationError -> 422 envelope with code validation_error and a
   request_id present; an unexpected exception -> 500 envelope with
   code internal_error and no traceback text; a clean GET /api/v1/
   healthz -> 200 {"status": "ok"}.
4. Update docs/architecture.md with the actual public interfaces of
   the opsledger/http/ package.

Acceptance:
- bash check.sh exits 0.
- python3 -m unittest tests.unit.test_http -v exits 0.
- Every error response body has exactly the envelope shape with a
  non-empty request_id; no response body ever contains a traceback.

Allowed paths: opsledger/http/, tests/unit/test_http.py,
docs/architecture.md. Preserve all bootstrap behavior and the
T001/T002 modules unchanged.

Constraints:
- No edits to check.sh, CI, or unrelated modules.
- No new external packages, network access beyond the loopback test
  server, credentials, or generated data.
- No deletion, skipping, or weakening of accepted assertions.
- Standard-library http.server only; bounded bodies and timeouts; no
  business rules in the adapter.
