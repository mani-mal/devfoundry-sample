Title: Add SQLite connection factory and transaction context

Prerequisites:
Accepted remote commit 3113b87 on main (T001: opsledger/core/errors.py,
opsledger/core/clock.py with ApplicationError/ValidationError and
RealClock/FixedClock, format_rfc3339, require_aware_utc; tests/unit/
test_core_errors.py, tests/unit/test_clock.py; docs/architecture.md
documents both modules; bash check.sh exits 0 with 32 Python + 2 JS tests).

Goal:
Create the persistence foundation used by every later business service.
This task does not add HTTP routes, authentication, business tables, or
business modules.

Current contracts:
- opsledger/core/errors.py: ApplicationError(message, *, code=None,
  fields=None) with .code, .fields, to_payload(); subclasses
  ValidationError, NotFoundError, PermissionDeniedError, ConflictError.
- opsledger/core/clock.py: Clock protocol (now() -> aware UTC datetime,
  timestamp() -> RFC3339 Z string), RealClock, FixedClock(instant),
  format_rfc3339(value), require_aware_utc(value).
- opsledger/core/__init__.py re-exports the public API above.
- No opsledger/core/db.py exists yet. No migrations exist yet.

Required behavior:
1. Add opsledger/core/db.py with a connection factory: connect(path)
   returning a sqlite3.Connection with foreign_keys=ON, journal_mode=WAL,
   synchronous=NORMAL, and row_factory=sqlite3.Row. Same-thread use only:
   set check_same_thread=True (the default) and document that connections
   are never shared across threads.
2. Add a transaction context manager: transaction(conn) that BEGINs an
   IMMEDIATE transaction, commits on clean exit, and rolls back on any
   exception, re-raising the original error. Nested use raises
   ConflictError (stable code "conflict") with a public message; no
   traceback text in the message.
3. Database errors from sqlite3 (IntegrityError, OperationalError) are
   re-raised as-is; do not swallow or wrap them into ValidationError.
4. Add package files where needed. Add tests under
   tests/unit/test_db.py covering: foreign_keys pragma is ON after
   connect; journal_mode is wal; a clean block commits (row persists);
   an exception inside the block rolls back (row absent, original
   exception propagates); nested transaction raises ConflictError;
   IntegrityError propagates unchanged.
5. Update docs/architecture.md with the actual public interfaces of
   opsledger/core/db.py.

Acceptance:
- bash check.sh exits 0.
- python3 -m unittest tests.unit.test_db -v exits 0.
- A connection from the factory has PRAGMA foreign_keys = 1 and
  journal_mode = wal.
- A row inserted inside transaction() persists after the block; a row
  inserted before a raised exception does not persist.
- Nested transaction() raises ConflictError with code "conflict".

Allowed paths: opsledger/core/, tests/unit/test_db.py,
docs/architecture.md. Preserve all bootstrap behavior and the T001
modules unchanged.

Constraints:
- No edits to check.sh, CI, existing migrations, or unrelated modules.
- No new external packages, network access, credentials, or generated data.
- No deletion, skipping, or weakening of accepted assertions.
- Standard-library sqlite3 only, parameterized SQL, explicit transactions.
