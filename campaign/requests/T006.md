What to build:

A. opsledger/cli.py — stdlib argparse with two subcommands, runnable via
python -m opsledger.cli:
- `migrate DATABASE [--migrations DIR]` (DIR default
  "opsledger/migrations"): connect with opsledger.core.db.connect,
  run opsledger.core.migrations.migrate(conn, dir), print each applied
  migration_id one per line, exit 0. On ConflictError/ValidationError
  print the public message to stderr and exit 1 (never a traceback).
- `serve DATABASE [--host H] [--port P]` (defaults 127.0.0.1 / 8080):
  run migrations first (same rules), build the router
  (opsledger.http.handlers.build_router()), serve with
  RouterServer until SIGINT/SIGTERM, then shutdown() + server_close()
  and exit 0 cleanly.

B. opsledger/http/handlers.py:
- `healthz_handler(request)` returning (200, {"status": "ok"}).
- `readyz_handler(request)` reading the database the router server was
  configured with: open the schema_migrations history table; missing or
  empty -> (503, {"error": {"code": "unready", "message": "the schema
  has not been migrated", "request_id": ...}}) built with
  opsledger.http.envelope.build_error_body; recorded history missing a
  shipped migration (compare against the migrations directory listing)
  -> 503 unready naming the first five missing ids sorted; otherwise
  (200, {"status": "ready", "migrations": N}). Never include paths,
  SQL, secrets, or traceback text. Unexpected errors inside readyz go
  through error_response_for (500 internal_error).
- `build_router()`: Router with GET /api/v1/healthz -> healthz_handler
  and GET /api/v1/readyz -> readyz_handler.

C. tests/unit/test_cli.py: migrate on a fresh temp database exits 0 and
prints 0001_initial then 0002_identity; second migrate exits 0 and
prints nothing; edited applied file -> exit 1, public message, no
traceback; readyz on an un-migrated database -> 503 unready; readyz
after migrate -> 200 {"status":"ready","migrations":2}; readyz with a
missing history row -> 503 naming it; readyz bodies never contain a
path or traceback; healthz end to end via RouterServer on
127.0.0.1 port 0 -> 200 {"status":"ok"}.
